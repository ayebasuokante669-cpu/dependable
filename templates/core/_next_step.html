{% load onboarding %}{% comment %} "That's done — here's what's next." The continuation that closes the dead end. A school that finished a setup step used to land back on a list with nothing to say what followed, and the onboarding checklist they came from was two clicks behind them. Takes `after` -- the key of the step this screen *is*, one of the step keys in views.onboarding_steps. The prompt appears only when that step is now done and something else is not, so: * it is never shown before the step it congratulates has been finished; * it goes by itself the moment the whole checklist is complete, rather than becoming a permanent strip of chrome on four screens; * it names the next step by reading the checklist rather than by hardcoding an order here, so adding a step changes one list and not five templates. Inline rather than a modal. A modal would interrupt somebody who came to this screen to do something else -- most visits to the class list are not the first one -- and the whole point is to offer a next step, not to insist on it. {% endcomment %} {% onboarding_progress as setup %} {% if setup and not setup.is_complete and setup.next_step %} {% for step in setup.steps %} {% if step.key == after and step.done %}
