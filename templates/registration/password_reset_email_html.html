{% extends "email/_base.html" %}{% load static %}{% comment %} The HTML half of the password-reset mail, on the shared platform email shell. Django sends it multipart alongside the plain-text `password_reset_email.html`, so a client that refuses HTML still gets a complete, readable message -- which is the only reason sending HTML at all is safe. This same message is what a *new* account receives: `invites.send_set_password_email` creates the account with a password nobody knows and then puts it through Django's own reset flow, so there is one email to keep working rather than two that drift. The wording has to read for both, which is why it says "choose a password for" and not "reset the password you forgot". `protocol` and `domain` are Django's, from `PasswordResetForm`; everything else -- `product_name`, `contact_email` -- comes from the branding context processor, which `BrandedPasswordResetView` hands in explicitly because a mail template renders with no request and no context processors. {% endcomment %} {% block subject %}Choose a new {{ product_name }} password{% endblock %} {% block preheader %} Your link to set a password.
