{% comment %} The sign-in panel: everything on the form side of the split, as one unit. Extracted from login.html so it can be rendered on *both* auth URLs. Having both panels in the DOM is what lets switching between them be an instant client-side animation instead of a page load -- see `initAuthSwitch` in js/ui.js. Takes `form`. On /signup/ that is the signup form, so the field values are read defensively: `login_form` is passed there instead and this partial is included with `form=login_form`. The form posts to its own URL explicitly rather than to whatever page it happens to be rendered on. Without that, signing in from the sign-up URL would POST the credentials at the signup view. {% endcomment %}
