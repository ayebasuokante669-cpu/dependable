{% extends "base.html" %} {% comment %} The sign-in / sign-up split panel, with **both** panels in the DOM. Used by /accounts/login/ and /signup/ alike. Each renders the same markup and differs only in `auth_panel`, which says which side starts showing. Because both forms are already present, switching between them is a class change and an animation -- no fetch, no navigation, nothing to wait for. js/ui.js (`initAuthSwitch`) also rewrites the URL with `history.pushState`, so the address bar, the back button and a bookmark all still agree with what is on screen. Without JavaScript the switch links are ordinary hrefs to the other URL and the page loads as it always did, showing that page's panel. The only thing lost is the instant transition. Each form posts to its own action, so a sign-in submitted while the URL says /signup/ still reaches the login view. The password-reset screens keep using _auth_base.html: they are one panel with nothing to switch to. {% endcomment %} {% block anonymous_content %}
