{% comment %} One toast. Takes `level` (success / error / warning / info), `label` (the category as a word) and `body` (the message). Ships with `is-in is-open is-lit` — risen, open and with its words showing — so the message is readable with no JavaScript at all. js/ui.js strips all three on load and plays the entrance properly. `is-lit` is the third state, and it is what fixes the crushed-text close: the words fade on their own, after the panel has opened and before it closes again. See the `.toast-panel > div` rule in assets/app.css. The icons are the same four glyphs js/ui.js draws for toasts it creates, so a message from the server and one raised in the browser are indistinguishable. {% endcomment %}
{% comment %} The dismiss button lives inside the panel, not beside it: anything outside would stay put while the panel collapsed, and the closed state would be a lozenge instead of a circle. Only the two levels that report a problem get one. A success or an informational toast has nothing to act on, so a control to dismiss it is one more thing on screen for no gain -- they simply go. {% endcomment %}
